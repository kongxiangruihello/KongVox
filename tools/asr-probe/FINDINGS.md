# 本机语音识别可行性实验（2026-10-08）

目的：判断 macOS 自带的 `SpeechTranscriber`（Speech 框架，macOS 26+）能否用于 KongVox 的漏读/重读检查与字幕对齐。

## 环境

- MacBook Pro 14 英寸，Apple M5，16 GB；macOS 27.0.1（26A434）。
- `SpeechTranscriber.isAvailable = true`；`zh_CN` 模型系统已预装（`installed` 中列出），无需下载。
- GitHub Actions `macos-26` 虚拟机：可编译，但 `isAvailable = false`、资产状态 `unsupported`，只能在真机测试。

## 样本

- 28 段现有配音（火山 2、Gemini 24、CosyVoice 2），约 9 分钟，1552 个音节；内容以《史记·孔子世家》《论语》为主，另有含数字的现代文。
- 人为改动样本 8 段：在停顿处删去或重复一个分句（0.4–3.2 秒）。

## 结果

| 指标 | 结果 |
| --- | --- |
| 速度 | 32 段共约 11 秒（约 50 倍实时） |
| 字错率（按汉字） | 21.4%，几乎全为同音字（古文生僻字被识别为常用同音字） |
| 音节错误率（按无声调拼音，数字转中文读法） | 2.8% |
| 时间戳 | 1870 个识别单元全部带起止时间，逐字，单调；与音频结尾偏差中位数 0 秒 |
| 置信度 | 每字提供；误认字通常明显偏低（如 0.4、0.52） |
| 漏读/重读检出（连续 ≥2 音节差异） | 有效样本 7/7；原始 28 段误报 0 |
| 未检出 | 1 个 0.4 秒重复样本（不足一个音节，样本无效） |

## 结论

按拼音而非汉字比对后，本机识别足以支撑「疑似漏读/重读」检查，并能用逐字时间戳定位；字幕对齐可利用同一比对结果把识别时间映射回原稿。

## 尚未验证

- App 内用 `CFStringTransform`（ICU Han-Latin）代替 pypinyin 时的多音字表现。
- 真实 TTS 故障（含混、读错、半句吞音）而非人为剪切的检出率；样本量较小。
- 很长片段（>1 分钟）与整篇长文的耗时、内存。
